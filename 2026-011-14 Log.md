We ran the rover via Xbox controller plugged into the jetson

### 1. Ethercat didn't work 
symptoms: 
- `ethercat slaves` was empty
- `ethercat master` said "Link: DOWN"

process/fixes
`ethercat master` had line "Main: [MAC address]" above the "Link: DOWN" line
using `ip -br link` shows the MAC addresses of all interfaces, the "Main:" one was for `eth0`
determined `eth1` is Henry's adapter, and found its MAC address

changed `MASTER0_DEVICE` to be that mac adddress in `/usr/local/etherlab/etc/ethercat.conf`

`sudo systemctl restart ethercat` to make the change take effect

`ethercat slaves` now shows correct info (not empty)

IMPORTANT:
- there's a `/etc/sysconfig/ethercat` which is *not the proper config file* (at least for this)

### 2. Xbox controller didn't work on jetson
symptoms:
- plugging in the controller didn't do anything (tested via gamepad tester website)

Fix:
```bash
sudo apt install dkms build-essential git
git clone https://github.com/paroj/xpad.git
cd xpad
sudo dkms install "$PWD"
sudo modprobe xpad
```

Further issues:
- having the gamepad plugged in has a constant weird effect on rustdesk interactions (almost like holding the up arrow key?) my temp fix was to unplug the controller whenever working on things

### 3. Running the rover
in `~/circ-2026`:

1. fixed skid driving throttle axis (was 4 for drone controller) to 5 for xbox controller (right trigger), scaling was unnaffected thankfully :)
2. colcon build and source install/setup.bash
3. in separate terminals, in order (source install/setup.bash when needed):
    1. `watch -n 0.5 ethercat slaves` to monitor ethercat device status
    2. `ros2 launch plex_ros2_control/launch/motor_drive.launch.py` to launch the ethercat controller, ros2_control stuff
    3. `ros2 topic echo /drive_velocity_controller/commands` to watch commands going to the motors
    4. `ros2 run joy joy_node` (joystick broadcaster)
    5. `ros2 run plex_ros2_control drive_skid` (actual drive code)

issues: some wheels spun backwards when turning, we fixed this by changing the WHEELS array's order and is_right=[T/F]
- This was a quick fix, and is wrong, works temporarily, but once firmware is rewritten/etc, a correct fix should be much easier

Xbox controller layout:
- right trigger: throttle input
- left stick horizontal axis: steering input
- A button: forward driving enable
- B button: backward driving enable
- left trigger: in-place-steering enable

moving any axes without one of the modes enabled does nothing
